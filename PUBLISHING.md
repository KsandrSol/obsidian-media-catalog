# Публикация в Obsidian Community

Пакет 0.2.0 — первая версия для проверки, ещё не заявка в официальный каталог. Владелец разрешил публикацию исходников под MIT в публичном репозитории KsandrSol/obsidian-media-catalog и предварительного GitHub-релиза 0.2.0. Подготовлены исходники, manifest, версии, инструкция, лицензия и 28 автоматических тестов. Заявка в Obsidian Community пока не отправляется: остаются проверки на устройствах и атрибуция TMDB.

## Что проверить до отправки

- Проверить на Mac: библиотека, встроенные cards/table Bases, кнопка добавления, поиск по русскому и английскому названию, TMDB с настоящим токеном, книга из Open Library и Google Books, выбор издания, повторное добавление, отключение плагина и возврат к обычным заметкам.
- Проверить на телефоне: те же сценарии, экранная клавиатура, локальное хранение токена, сеть, закрытие окна во время поиска, повторный запуск после синхронизации.
- Проверить минимальную версию 1.9.0 и повысить её, если используемый API или Bases недоступны. Заявленная совместимость сейчас не проверена в настоящем приложении.
- Добавить официальный логотип TMDB в раздел атрибуции; сверить все требования поставщиков данных. Логотип не включён в этот пакет.
- Проверить уникальность публичного ID и подготовить демонстрационные скриншоты без личных данных. MIT-лицензия и автор ksandrsol подтверждены владельцем для этого предварительного релиза. Смена текущего ID потребует переустановки и повторного ввода ключей.
- Провести проверку по актуальным submission requirements и plugin guidelines. Воспроизводимый package-lock.json уже подготовлен; сборка пока копирует проверенный исходный JavaScript, без минификации.

## Как отправить

1. Разместить только исходники плагина в публичном GitHub-репозитории. README.md, LICENSE и manifest.json должны быть в корне основной ветки. Личные заметки, My Clippings.txt и ключи в репозиторий не входят.
2. Собрать main.js и создать GitHub Release. Тег должен совпадать с version в manifest, например 0.2.0, без префикса v. Прикрепить main.js, manifest.json и styles.css отдельными release assets; одного ZIP недостаточно.
3. Войти на https://community.obsidian.md с аккаунтом Obsidian, привязать GitHub, открыть Plugins → New plugin и указать репозиторий и владельца.
4. Принять правила разработчиков, отправить заявку и исправить замечания автоматической проверки. Если меняется код, выпустить новый релиз с новой версией. До завершения проверки плагин не будет доступен для установки из Obsidian.
5. Поддерживать совместимость и выпускать дальнейшие обновления через GitHub Releases. Первичную заявку не требуется отправлять при каждом обновлении.

Проверено по официальной документации 12.10.2026: https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin и https://docs.obsidian.md/community-directory/set-up-and-claim. Это текущий маршрут подачи через сайт; прежние инструкции про PR в obsidian-releases могут быть устаревшими.
